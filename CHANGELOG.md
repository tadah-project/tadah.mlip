# Changelog

This is the **umbrella changelog** for the Tadah! framework — the curated, cross-module view that users browsing the umbrella repository read first. Each entry is prefixed with the originating module:

- `[core]` — Tadah.CORE (blueprint / config / registry)
- `[mlip]` — Tadah.MLIP module (training / predict / data-balance orchestration)
- `[models]` — Tadah.MODELS (descriptors / cutoffs / basis functions / regressors)
- `[md]` — Tadah.MD (lightweight MD drivers)
- `[hpo]` — Tadah.HPO (hyper-parameter optimisation)
- `[lammps]` — Tadah.LAMMPS (`pair_tadah` LAMMPS plugin)
- `[umbrella]` — this repository (`tadah` binary, docs site, examples)

For the full per-module commit-level log, see each module's own `CHANGELOG.md`.

Format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/);
versioning follows [SemVer](https://semver.org/) at the umbrella level.

### Changed
- `[hpo]` **A point the run has evaluated is answered from its evaluation when a search asks for it again, if every evaluation of the run is a function of its point** (NLopt and `DLIB:BFGS`): the run records each evaluation with a usable loss by the point evaluated, whichever search or backend asked for it, and a call at such a point, the same doubles bit for bit, that asks for nothing the record lacks (a gradient only when the same search formed one there) gets its loss without an evaluation -- a point the search asked for before, `LD_MMA` and `LD_CCSAQ` landing on the same clamped corner again, `LN_SBPLX` and `LN_NELDERMEAD` reflecting onto a bound point, `LD_SLSQP` and `LN_COBYLA` stepping onto a bound point they had, `AUGLAG` evaluating the point its local search returned once more, `DLIB:BFGS`'s line-search trials clamped onto one point -- or one an earlier search of the run evaluated: a `PRESTAGE` refinement's start (the exploration's best), a point an earlier `MULTISTART` start reached, a `RESTART` round from `METHOD CONFIG` retracing round 0. No row, and not counted in HPO's count of evaluations, which counts each search's own and is what `DLIB:BFGS`'s `MAXEVAL` (and so a `BUDGET_PER_START`, a `PRESTAGE` phase's `MAXEVAL`) bounds; NLopt counts every call against its own `MAXEVAL`, one answered from an earlier search's evaluation too, so an NLopt phase or start is charged for it (an `LN_SBPLX` refinement of `MAXEVAL 4` whose first call is the exploration's best makes 3 evaluations); the journal names an earlier search's evaluation as such. Each search evaluates its own gradients' stencils. A `PRESTAGE` exploration's call answered from the record is a candidate for the refinement, as its evaluation would be, so an exploration that retraces an earlier round still hands its candidates on. Under `GRAD_STRATEGY NUMERICAL` a call that asks for a gradient the record lacks takes the recorded loss as the loss at the point of its finite differences, whose stencil alone is evaluated (MLSL's local search asks for the gradient at a sample it evaluated without one, and each local start was evaluated again); under `ANALYTICAL` and `HYBRID` the point is evaluated, and when `DLIB:BFGS` asked for its loss just before (at its start, or where a line search ends) that evaluation answers the loss call too, one evaluation and no reuse (a `PRESTAGE` refinement's start is evaluated once and counted once in the `RESTART` window). The `RESTART` window counts each such call as one evaluation without a new best: a search that only asks for points the run has makes no evaluation, and the window still ends or relaunches it (`LD_MMA` held at a bound with `RESTART` as its only stop), and its `StagnationStop` line counts such calls. A run whose loss has a `PC_LAMMPS` line (LAMMPS instances kept from one evaluation to the next, the `--hotvar` chain), a `PC_OBSERVABLE` that carries state (`cohesive_energy`'s lattice constant) or a `--skip-rel` filter evaluates every repeat again, as every run did, and counts as repeats evaluated again the points an earlier search of the run evaluated (a `PRESTAGE` refinement's start; HPO example 12: `Repeats evaluated again : 5`, 2 while each search's record was its own), naming them as an earlier search's. A repeat of a failed evaluation is evaluated again too, and so is one that asks under `ANALYTICAL` or `HYBRID` for a gradient its evaluation did not form. The journal names the first reuse of each search and, once, why a repeat is evaluated again; DIAGNOSTICS has `Repeated points reused` and `Repeats evaluated again`. NLopt counts a reused call among its own calls (its `MAXEVAL`): a derivative-free search still ends after `MAXEVAL` calls, with fewer evaluations, and its `MAXEVAL_REACHED` line says how many calls were answered, as the journal's first-reuse line and DIAGNOSTICS say; a gradient search can get further within its `MAXEVAL`, unless it mostly asks again (`LD_MMA` held at a bound: 18 evaluations of `MAXEVAL 60`, NLopt's count ending it). On a 2-D search on the HPO examples' Ta data (not one of the examples: `PC_ERMSE` and `PC_FRMSE`, `OPTIM RCUT2B (1) 4 6` and `CGRID2B (2) 0.1 2.0`, the optimum on a corner) `LD_MMA` and `LD_CCSAQ` at `MAXEVAL 40` make 10 evaluations where they made 20, `LN_SBPLX` 45 of its 60 calls; `LD_SLSQP`'s steps onto that corner are distinct points and are evaluated. - `[core][hpo]` **A second Ctrl-C (SIGINT), or a second SIGTERM, ends `tadah hpo` at once**, killed by the signal (a shell reports 130, 143; `tadah: second SIGINT: ending at once`), as `kill -9` would: `best_pot.tadah` keeps the last best it saved, and the history files can lack the rows still queued. The first signal still stops the run once the evaluations in progress finish, and is now announced at once on standard error (`tadah: SIGINT received: stopping once the work in progress can stop and save its results; a second SIGINT (Ctrl-C) ends tadah at once, and what is not yet written is lost`). Signals of different kinds (SLURM's `SIGTERM` after its `SIGUSR2` warning) and a second `SIGUSR2` do not escalate. `PC_ISOLATION PROCESS` workers die with `tadah`. A second signal did nothing, so a run inside a long evaluation (a LAMMPS run, a slow fit) could be ended only with `kill -9`. ## [1.6.0] — 2026-09-25

A clean-up release for wider testing: one version everywhere, documentation that matches the code, and a set of small nested-fitting fixes.

**BREAKING for DM_REAM potentials:** the density form `RHOFORM` is mandatory; add `RHOFORM SIGNED` to a DM_REAM potential or configuration written before 1.6.0 to use it unchanged (see *Changed*).

**BREAKING for multi-species BIAS potentials:** with `BIAS true` every atom has one intercept column per `ATOM` species on every path. A potential trained with `BIAS true` and two or more species by an earlier version has one intercept column shared by the species (its LAMMPS energies and forces were wrong with `pair_style tadah` 1.3.0-beta.1 and later, which used one column per species; with 1.2.0 and earlier they matched `tadah predict`); `tadah predict` and `pair_style tadah` refuse it: retrain it (`tadah train -c` with its training configuration, or with the potential itself: an `M_BLR` potential of those versions records its `DBFILE`, so train from it as it is or replace that line with the `DBFILE` of the retrain, and add a `DBFILE` line to an `M_KRR` one; *Training*, *Retraining from a potential*). Training data whose compositions cannot determine the per-species constants are refused, and `FIXINDEX` indices of descriptor weights start at N + 1 (see *Changed*). Single-species potentials are unchanged.

**BREAKING for `tadah predict --error` and `tadah train --uncertainty`:** an `OALGO 3` potential carries the covariance of its weights, `WCOV`, and the noise variance of its fit, `WNOISE`, and `--error` reports the predictive standard deviation of each value. The `SIGMA` of earlier potentials (Tadah! 1.0.0 to 1.5.0 and 1.6.0 development builds) was computed with a transposed formula and is ignored, so `--error` refuses those potentials: retrain them with `OALGO 3`. Every `--error` and `--uncertainty` number changes (the old ones were wrong). The λ and the weights of a `LAMBDA -1` fit change, by orders of magnitude in λ when the fit has many rows of weight 0 (see *Changed*).

**BREAKING for `tadah refit` in builds without the compact fitter:** a `tadah` built without `TADAH_ENABLE_NFP`, or with it but with `TADAH_ENABLE_CERES` off (`-DTADAH_ENABLE_CERES=OFF`), has no compact fitter and refuses `REFIT_MODE compact`, written or the default (a configuration without `REFIT_MODE` asks for it), before it reads the EAM file (`tadah refit: REFIT_MODE compact (the default) needs the compact fitter, which this tadah was built without ...; set REFIT_MODE dense`); it fitted the table in dense mode after a WARNING. Add `REFIT_MODE dense` to every refit configuration of such a build (see *Fixed*; *Installation* says so under `TADAH_ENABLE_CERES`).

**Behaviour change for bounded gradient searches:** `tadah hpo`'s finite-difference gradients no longer evaluate outside the `OPTIM` box, with either step rule (`PARAM fd_kernel inhouse` or `ceres`); within a step of a bound they are one-sided, so a search whose gradient reaches a bound can take a different path, and a box too narrow for the step, `diff_method 2` (RIDDERS) and finite-difference settings that never take effect (the `NOISE` block's `AUTO` included) are refused at startup (see *Changed*).

**NLopt's `MAXEVAL` counts every evaluation:** each loss, each finite-difference point and each analytical gradient, as with `DLIB:BFGS` and CERES; an NLopt gradient search made up to about twice `MAXEVAL` evaluations, and an `ANALYTICAL` one up to `MAXEVAL` losses and as many gradients, so with the same `MAXEVAL` such a search now does less: raise `MAXEVAL` to keep the old totals. `GD_STOGO` and `GD_STOGO_RAND` now need `MAXEVAL`; `MAXTIME`, `STOPVAL` or `RESTART` alone is a startup error (see *Changed*).

**`tadah hpo`'s journal trailer says why the search ended:** `Optimiser status` names the stop (`DLIB:BFGS: MAXEVAL reached`, `TADAH:ANNEAL: STOPVAL reached`, `CERES:LBFGS: FTOL_REL reached`, NLopt's `MAXEVAL_REACHED -- …`) and `COMPLETED` is no longer written. A job script that looked for `COMPLETED` no longer matches: test `tadah`'s exit status, not the status text (see *Changed*).

**Check datasets converted by older versions:** the lattice vectors are the rows of a dataset's cell block. Datasets converted from a VASP OUTCAR or a CASTEP `.castep`/`.md`/`.geom` file before 1.3.0-beta.1 store the cell of a non-symmetric structure transposed, those converted from a `vasprun.xml` before 1.3.0-beta.1 have wrong positions, and VASP/LAMMPS/CASTEP files that `tadah data write -s` exported from a non-orthogonal CIF/COD entry before 1.6.0 have a transposed cell. `tadah analysis dataset_stats` lists the structures that can be affected; *Dataset Format* in the docs says how to repair them (see *Fixed*). Potentials and `tadah hpo` results fitted to affected structures need to be regenerated.

**Neighbour lists are exact for any cell:** every periodic image within the cutoff is now found for cells thinner than the cutoff in some direction, triclinic cells and atoms outside the cell (before, e.g., a 2-atom bcc cell with a = 3.41 Å at a 10 Å cutoff kept 168 of each atom's 180 neighbours). Training, `tadah predict` and `tadah hpo` change for such structures, and now agree with `pair_style tadah`; retrain potentials fitted to them (see *Fixed*).

**Re-convert VASP data:** the stored stress is the Cauchy stress in eV/Å³, positive under tension, from every reader, and the stored DFT energy is the free energy F, whose gradient the forces are. Datasets converted from a VASP OUTCAR or `vasprun.xml` by Tadah 1.0.0 to 1.5.x, or by a 1.6.0 development build without this change (the version number does not tell them apart), hold VASP's pressure sign (a `STRESS true` fit on them fitted the negated stress) and the energy without entropy (OUTCAR) or energy(σ→0) (`vasprun.xml`); re-convert them (*Dataset Format* in the docs says how to tell). CASTEP `.md` data converted by those builds still hold the kinetic stress; re-convert those too (see *Changed*).

### Changed
- `[core][models][mlip][hpo][lammps]` **BREAKING for `tadah predict --error` and `tadah train --uncertainty`: the weight covariance of an `OALGO 3` potential is `WCOV` and `WNOISE`, and `--error` reports the predictive standard deviation.** Every `SIGMA` written by Tadah! 1.0.0 to 1.5.0 (and 1.6.0 development builds) was wrong: computed with a transposed formula (VᵀRV instead of VRVᵀ) and without the noise variance, so every `--error` and `--uncertainty` number was wrong too, and most force errors were negative. ## [1.5.0] — 2026-09-10

### Breaking
- `[hpo][umbrella]` **BREAKING — `PARAM` value vocabulary is `ON` / `OFF` / `AUTO`.** Numeric booleans (`CORANA 1`) and `0`-means-disabled (`SWAP_WINDOW 0`) are gone across the whole OPTIMIZER block, and `BOUNDARY_MODE` became the enum `REFLECT | REDRAW`. `0` had drifted into meaning three different things on neighbouring keys. Old spellings are hard errors naming the replacement.
- `[hpo][umbrella]` **BREAKING — every index a person reads is 1-based**, in the sidecar TSVs and `best_pot.tadah`'s `# HPO_SOURCE_SLOT` header as well as `hpo_run.log`. Internally they stay 0-based (they are cache and checkpoint identities), so the conversion happens at the I/O boundary. Scripts parsing a slot number must subtract one.
- `[hpo][umbrella]` **BREAKING — `ANNEAL_PT` ladder-scales the initial jitter by default** (`PARAM INIT_JITTER_LADDER AUTO`): slot *k* is displaced by `sigma*(T_k/T_HOT)^0.5` instead of every slot sharing one sigma, so a warm start survives at the cold end. Changes the starting population of existing PT runs at a fixed `SEED`; `OFF` restores the previous placement exactly.
- `[hpo]` ASA's per-dimension `PARAM Name[i]` indices are now 1-based, matching the dimension numbers the run prints (`hpo_search_space.tsv`, journal `SEARCH SPACE`); `[0]` is a hard error naming the change (BREAKING for ASA configs using the indexed form).
- `[hpo]` Dimension labels are `KEY[n]` with `n` the OPTIM index (1-based; the model weight for `FIXWEIGHT`) everywhere -- journal, `params.tadah`, `hpo_step_scales.tsv`, sidecars -- instead of the 0-based token position (BREAKING for scripts parsing `KEY[i]`; reference fingerprints regenerated). `tadah hpo` no longer dumps the per-key bounds table to stdout; `hpo_search_space.tsv` drops the `key`/`optim_index` columns, gains a comment header (incl. what `version` means) and aligned, space-padded tab-separated columns.

Documented on a dedicated docs page (`asa.rst`) with option tables, deviations from upstream defaults, and Ingber's tuning guidance; example `21_asa` added.
- `[hpo][umbrella]` `ANNEAL_PT` supports opt-in endpoint-preserving temperature adaptation (`LADDER_ADAPT`) from a configurable power-shaped log ladder (`LADDER_POWER`), with diminishing gain, finite-freeze controls, MPI-identical updates, per-update journal tables, and `hpo_temperature_ladder.tsv`; legacy runs remain geometric and unchanged unless a new ladder knob is supplied.
- `[hpo][umbrella]` `PARAM SWAP_WINDOW` controls `ANNEAL_PT` windowed per-pair swap-acceptance reporting (default `20`; `0` keeps cumulative reporting only).
- `[hpo][umbrella]` Annealing boundary policy: `PARAM BOUNDARY_MODE 0` keeps exact mirror reflection as the default; `1` uses Corana-compatible per-coordinate redraw without spending host-evaluation budget on discarded draws.

A pre-rename SIGKILL may leave an ignored hidden temporary file but never a torn canonical potential.

- `[hpo][umbrella]` **Search-space scaling layer.** Every `OPTIM` dimension now has a shape tag (`LIN | LOG | ASINH <c>`), the root key `OPTIM_SCALE AUTO | NONE` maps the whole box to the unit cube (`AUTO` is the new default; `NONE` = legacy coordinates, byte-identical to earlier runs), `STEP` is a fraction of each dimension's width handed to NLopt per dimension (with `STEP <KEY>[(i)] <frac>` overrides) and is rejected by backends that ignore it, `PARAM GRID_POINTS` replaces GRID's `STEP` overload, `OPTIM ... AUTO` derives seed-relative boxes, and `hpo_run.log` prints the search space, the effective per-dimension step and a bound-occupancy audit. ## Migrating from v1.2.0 to 1.3.0-beta.1

> **Tag note.** No `v1.2.0` git tag was ever pushed; the most recent git tag in every module is `v1.1.1`. The blueprint TOML `version = "1.2.0"` field was bumped during the playground era but never tagged. In practice, "migrate from 1.2.0" means "migrate from `v1.1.1` head as of late 2025 / early 2026".

### Breaking changes

1. **`Cut_PT` normalisation (`[models]`).** The polynomial cutoff `Cut_PT` was previously off by a constant; it has been fixed to satisfy `f(0) = 1`. Any potential trained against v1.1.x with `RCUT_TYPE Cut_PT` will produce numerically different energies / forces / stresses on the new build. **Action:** retrain the affected potential, or pin the older Tadah.MODELS commit if reproducibility against an existing pot.tadah is required for your workflow.

2. **C++17 toolchain (`[core][mlip][models][md]`).** The minimum compiler standard moved from C++14 to C++17. **Action:** ensure GCC ≥ 7, Clang ≥ 5, or equivalent. CMake will fail at configure if the compiler is too old.

3. **Blueprint key casing: `atom` → `ATOM` (`[core]`).** The schema now uses upper-case `ATOM` consistently. **Action:** if you have hand-written input files using the lowercase form *and* you parse with a case-sensitive tool, capitalise. The Tadah! parser itself is case-insensitive for blueprint keys, so most users are unaffected.

4. **`set_project_name` CMake shim deprecated (`[umbrella]`).** Out-of-tree CMake users that called `set_project_name(...)` directly will see a deprecation warning. The shim still works as a one-line forward; it will be removed in a future release. **Action:** switch to `tadah_read_version_from_blueprint(TADAH_VERSION REQUIRED)` + standard `project(... VERSION ${TADAH_VERSION})`.

### Behavioural changes that don't break compilation but may change results

1. **`tadah data balance` defaults (`[core]`).** The `[TASKS.data.balance.keys.threshold]` default tightened from `["1e-1", "2e-2", "3e-3"]` to `["1e-4", "1e-5", "1e-6"]`. Runs that relied on the old defaults will now treat far more configs as outside threshold (and rescale them). **Action:** if you want the v1.1.1 behaviour, pass `THRESHOLD 1e-1 2e-2 3e-3` explicitly.
2. **`THRESHOLD` top-level default removed (`[core]`).** The top-level `THRESHOLD` ALLOWED_KEY no longer carries a `default_value = ["1e-6"]`. Tasks that previously inherited this default may now require an explicit value. **Action:** set `THRESHOLD` explicitly in your blueprint section if a task complains.
3. **`HPO best_pot` writer v2 (`[hpo]`).** The output layout differs from v1.1.1; downstream parsers should be re-validated. **Action:** re-run any post-processing scripts on a known fingerprint.
4. **`DM_mEAD` warning (`[models]`).** No behavioural change at runtime, but `DM_mEAD` with `L > 0` and `F ≠ F_SQ` now emits a load-time warning about its rotational-invariance defect. **Action:** ignore for legacy potentials; for new work, switch to a `DM_PS_*` descriptor.
5. **`TADAH_HPO_HOT_A0_*` and `TADAH_HPO_BAD_POT_ERMSE_*` env vars removed (`[hpo]`).** All five environment variables (`TADAH_HPO_HOT_A0_DEFAULT`, `TADAH_HPO_A0_MIN`, `TADAH_HPO_A0_MAX`, `TADAH_HPO_BAD_POT_ERMSE_MEV`, `TADAH_HPO_BAD_POT_ERMSE_REL`) no longer have any effect; the parser does not consult `getenv()`. **Action:** replace the `${hot_a0}` script convention with explicit `PC_LAMMPS --hotvar hot_a0 <min> <max> [<initial>]` on the producing line; replace `TADAH_HPO_BAD_POT_ERMSE_MEV=N` with `PC_ERMSE … --skip-above N`.
6. **`best_pot.tadah` warmstart-cache header (`[hpo]`).** The producer-side header line changed from `# HOT_A0 <script> <a0>` to `# HOT <script> <name> <value>` (multiple hot variables per script supported). Older `best_pot.tadah` files still parse on read for back-compat. **Action:** none for consumers; writers should expect the new format on subsequent runs.

### Deprecations
- `[models]` `DM_mEAD` with `L > 0` and `F ≠ F_SQ` — still works, prefer `DM_PS_*`.
- `[umbrella]` `set_project_name` CMake shim — still works, prefer `tadah_read_version_from_blueprint`.

### What's the same

All v1.2.0 / v1.1.1 blueprint inputs still parse (the `atom` / `ATOM` rename is handled case-insensitively by the parser, and `TYPEMB DM_<name> <mu> <nu> <El1> <El2>` still matches the 2-UINT regex form). Default behaviour is unchanged for `tadah train`, `tadah predict`, and the `pair_tadah` LAMMPS pair-style (other than the per-step bias precomputation, which only affects performance). Existing `pot.tadah` files load and predict; **only** potentials trained with `Cut_PT` will produce numerically different results — a retrain is the cleanest path forward. *Erratum (1.6.0):* 1.3.0-beta.1 also fixed the cell convention of the OUTCAR, CASTEP `.castep`/`.md`/`.geom` and `vasprun.xml` readers (the lattice vectors are the rows of `Structure::cell`), which changes the results of every structure with a non-symmetric cell; datasets converted before it may hold a transposed cell or wrong positions — see the 1.6.0 notes.
